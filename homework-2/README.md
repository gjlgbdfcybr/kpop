# ПОС — преподавательская оценка студентов

Учебное консольное приложение на C++17.

## Сборка и запуск

Откройте терминал в этой папке. Нужен g++ с поддержкой C++17.

```powershell
g++ -std=c++17 -Wall -Wextra main.cpp domain.cpp application.cpp adapters.cpp -o app.exe
.\app.exe
```

Тесты собираются отдельно от main.cpp:

```powershell
g++ -std=c++17 -Wall -Wextra tests.cpp domain.cpp application.cpp adapters.cpp -o tests.exe
.\tests.exe
```

## Возможности

- Добавить студентов и критерии, посмотреть списки и их ID.
- Выставить оценку по ID студента и критерия. Повторный ввод заменяет прежнюю оценку.
- Посмотреть оценки или отменить оценку.
- Рассчитать результаты всех студентов по шкале от 0 до 10.
- Экспортировать результаты в CSV с указанием режима расчёта.
- Пункт 9: выбрать Final или Preliminary. По умолчанию включён Final.
- Пункт 10: собрать рубрикатор целиком с проверкой критериев до сохранения.

Данные хранятся в памяти до выхода. CSV содержит только итоговую ведомость, загрузки из него нет. Пункт 0 завершает работу; конец ввода также завершает программу. При неправильном вводе выводится ошибка и снова появляется меню.

## Правила расчёта

Названия не могут быть пустыми или состоять только из пробелов. ID выдаются автоматически, начиная с 1. Одинаковые имена допустимы: сущности различаются по ID.

Максимальный балл должен быть конечным и положительным. Вес конечный, больше 0 и не больше 1. Сумма весов не обязана равняться 1: при расчёте веса нормализуются. Оценка конечная, от 0 до максимума критерия включительно. Несуществующие студенты и критерии не принимаются. На пару студент–критерий приходится не более одной оценки.

`Итог = 10 × сумма((балл / максимум) × (вес / сумма всех весов))`

В режиме Final отсутствующая оценка даёт нулевой вклад, но вес её критерия остаётся в знаменателе. В режиме Preliminary в знаменателе учитываются только критерии с выставленными оценками. Выставленный ноль считается оценкой, а пропуск — нет. Если оценок пока нет, предварительный результат равен 0 и не означает завершённую аттестацию. Если критериев нет, расчёт и экспорт отклоняются. Итог не хранится отдельно: после изменения оценки он пересчитывается. Округление до двух знаков применяется только при выводе и экспорте.

Пункт 2 по-прежнему добавляет один критерий с нормализацией весов при расчёте. Пункт 10 собирает рубрикатор целиком: Builder проверяет каждый критерий и требует непустой набор. Веса нормализуются так же, как при вводе по одному; сумма 1 не требуется. До успешной сборки ведомость не меняется. Установить набор можно только при пустом рубрикаторе, чтобы не сломать существующие оценки. При ошибке черновик из меню отменяется; ввод набора нужно повторить. После установки можно добавлять критерии пунктом 2.

## Сквозной сценарий

1. Пункт 1: добавить Alice, затем Bob. Их ID — 1 и 2.
2. Пункт 2: добавить Exam с максимумом 20 и весом 0.6.
3. Пункт 2: добавить Homework с максимумом 10 и весом 0.4.
4. Пункт 4: студент 1, критерий 1, балл 10.
5. Пункт 4: студент 1, критерий 2, балл 10.
6. Пункт 7: Alice получает 7.00, Bob — 0.00.
7. Пункт 8: ввести `results.csv`. Файл появится в текущей папке; существующий файл с этим именем перезаписывается.
8. Пункт 4: изменить балл Alice по Exam на 20. Итог станет 10.00.
9. Пункт 5: удалить оценку Alice по Homework. Итог станет 6.00.
10. Пункт 9: выбрать 2 (Preliminary). Итог Alice станет 10.00, потому что оставшаяся оценка Exam максимальная. Экспорт будет содержать режим Preliminary. Вернуться к Final можно пунктом 9, выбрав 1.
11. Попытаться поставить 21 по Exam или выбрать критерий 99: ошибка, прежние данные сохраняются.

Для проверки Builder начните новый запуск: пункт 10, два критерия Exam (20, 0.6) и Homework (10, 0.4). Затем продолжите сценарий с добавлением студентов и оценок. Набор с весами 0.6 и 0.3 допустим. Если у второго критерия ввести максимум 0, весь ввод из меню отменяется и первый критерий тоже не сохраняется.

CSV использует запятую как разделитель и точку в числах. Имена заключаются в кавычки; внутренние кавычки удваиваются. Экспорт не изменяет оценки. Для имён на русском кодировка терминала должна поддерживать UTF-8; для демонстрации можно использовать латиницу.

## DDD

Язык модели: Student (студент), Criterion (критерий), Evaluation (оценка), Gradebook (ведомость), FinalScoreService (расчёт итога).

Student и Criterion — сущности с постоянными ID. Evaluation определяется парой ID студента и критерия. Score — объект-значение без собственного ID: важна числовая величина, не история отдельного объекта.

Gradebook — корень агрегата: содержит студентов, рубрикатор и оценки одного курса. Только его методы меняют списки; наружу выдаются константные ссылки. Это позволяет проверять принадлежность студента и критерия ведомости и не допускать дубликатов оценок. Проверки чисел и названий находятся в конструкторах; верхнюю границу балла проверяет Evaluation. При исправлении сначала создаётся допустимая оценка, затем заменяется прежняя.

FinalScoreService — доменный сервис: расчёт использует рубрикатор и оценки, а не одну сущность. GradebookRepository — порт доступа к агрегату. В этой версии MemoryRepository хранит одну ведомость в памяти.

## Архитектура

Облегчённая Ports and Adapters. Слои разделены файлами, без отдельных папок и проектов:

| Файлы                             | Ответственность                              |
| --------------------------------- | -------------------------------------------- |
| domain.hpp / domain.cpp           | Модель, инварианты, расчёт, порт репозитория |
| application.hpp / application.cpp | Сценарии приложения и порт экспорта          |
| adapters.hpp / adapters.cpp       | Хранение в памяти, CSV, сборка зависимостей  |
| main.cpp                          | Консольный интерфейс                         |
| tests.cpp                         | Проверки без стороннего тестового фреймворка |

Зависимости: консоль и адаптеры → Application → Domain. Domain использует только стандартные типы C++ и ничего не знает о консоли и файлах. Application обращается к хранению и экспорту через интерфейсы.

Container — небольшой специализированный DI-контейнер: владеет репозиторием, двумя стратегиями, калькулятором и экспортом и передаёт их Application через конструктор. Универсальной регистрации типов нет. Контейнер должен жить дольше созданного приложения; в main порядок создания это обеспечивает. В тесте экспорт подменяется без изменения Application.

## Паттерны GoF

| Группа        | Паттерн                  | Задача                                                                                                                                  |
| ------------- | ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| Порождающий   | Builder — RubricBuilder  | Поэтапно собрать критерии и проверить весь набор до установки в ведомость. Ошибка последнего критерия не оставляет частичный рубрикатор |
| Структурный   | Facade — Application     | Предоставить консоли единую точку сценариев, скрыть доступ к репозиторию, расчёту и экспорту                                            |
| Поведенческий | Strategy — ScoreStrategy | Менять правило обработки пропущенных оценок без изменений консоли, CSV и общей формулы                                                  |

FinalStrategy возвращает вес любого критерия, PreliminaryStrategy возвращает нулевой вес для пропуска. Сервис применяет полученный вес к общей формуле без проверки режима. FinalScoreService хранит ссылку через указатель на выбранную стратегию и использует её правило. Application переключает стратегию, поэтому экран и экспорт всегда используют один режим. Стратегии должны жить дольше калькулятора; в Container они созданы раньше него. Копирование и перемещение Container запрещены: калькулятор ссылается на стратегии внутри него.

## Тесты

Шесть групп: сборка рубрикатора без частичного сохранения; переключение стратегий, пропуски и выставленные нули; недопустимые значения; границы и исправление оценок; взвешенный итог с нормализацией и пропусками; подмена экспортера и независимость контейнеров. Ошибка приводит к ненулевому коду возврата. Дополнительно сквозной сценарий выше проверяет консоль и экспорт.
